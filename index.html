The Information Commissioner's Office (ICO) is the UK's data-protection regulator. Think of it like: Organisation holds people's personal data → organisation has a responsibility to protect it → ICO can investigate when that protection fails. In August 2026, the ICO announced the outcome of its investigation into ACRO. The big problem: patching This is probably the easiest part of the story to discuss in your application. Imagine a company uses a piece of software. A security vulnerability is discovered in that software. The software provider releases a patch. A patch is essentially an update that fixes the vulnerability. So: Vulnerability discovered → security patch released → organisation installs patch → vulnerability is fixed/mitigated But if the organisation doesn't install the patch, the vulnerable system can remain exposed. That's particularly dangerous because once vulnerabilities become publicly known, attackers can actively search for organisations that haven't patched them. The ICO found that ACRO had inadequate patch-management processes. And there's another interesting issue: responsibility This is where the story becomes relevant to governance and risk, not just technical cyber security.
